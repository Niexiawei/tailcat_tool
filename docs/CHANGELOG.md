# 变更记录（CHANGELOG）

本文件记录本项目的**所有用户可见变更**。格式参考 [Keep a Changelog](https://keepachangelog.com/zh-CN/1.1.0/)，
版本号遵循 [语义化版本](https://semver.org/lang/zh-CN/)。

## 记录规则（对贡献者与代理同样有效）

1. **每个改动用户行为的提交，都必须在同一次提交里更新本文件。** 判断标准很简单：用户能感知到（界面、行为、文案、配置格式、文件位置、体积、依赖要求）。纯重构、纯测试、纯内部整理不必单独记一条，除非它改变了行为。
2. 写在最上面的 `## [未发布]` 里，按类别归入：`新增` / `变更` / `修复` / `移除` / `安全` / `依赖`。没有内容的类别不要留空标题。
3. 一条一行，**以用户视角描述结果**，而不是罗列函数名：
   - 好：`设备编辑器新增“本地 ADB 直连”，可填 IP:端口 或 USB 序列号`
   - 差：`add DirectADB field to Profile`
4. 需要解释"为什么"时，另起一行缩进说明；重大取舍请在 `docs/architecture.md` 的「设计决策记录」里补一行，而不是塞进这里。
5. 破坏性变更（配置文件格式、文件位置、去掉的功能）必须写进 `变更` 或 `移除`，并在条目末尾标注 **（破坏性）**。
6. 发布时把 `未发布` 改成 `## [x.y.z] - YYYY-MM-DD`，并在文件顶部补一条链接；不要事后修改已发布的段落。

## [未发布]

### 新增

- 启动时如果配置、历史库、系统凭据库、应用信息缓存打不开，或者找不到 adb，会先出现「启动时发现问题」页：**一次列出全部问题**（标题、具体原因、涉及的文件路径），每条都给出对应的动作（打开配置目录 / 打开工具设置），底部可以选择「用默认设置继续」或「退出」。以前只保留第一条问题，修好一个、重启一次才看见下一个。
- 有待处理的设备时，托盘会提示：macOS 菜单栏图标旁显示数量（如 `2`），鼠标悬浮显示「Tailcat Manager · 2 项待处理」，菜单第一项是可点击的「⚠ 2 项待处理」，点一下就唤回窗口（Windows / Linux 没有菜单栏数字，靠这一项）。数量按**设备**算：一次聚合提示挂几台就是几。处理完自动消失。
- 提供安装包与版本号：macOS（`.app` + `.dmg`）、Windows（可执行文件 + 安装器）、Linux（`.deb` / `.rpm` / `.tar.gz` / `PKGBUILD`），`tailcat-manager --version` 打印版本（普通 `go build` 的产物打印 `dev`）。
- 发布包内嵌终端插件（libghostty-vt）：装好之后**首次**打开「终端」页也不用联网下载。
- 应用图标换成 Android 终端图标（1024×1024）；托盘图标随之更换，并跟随任务栏明暗自动切换（浅色任务栏用深色版，深色任务栏用浅色版）。

### 已知限制

- Tailcat 转发通道（`tc…` 连接地址）这一轮**没有对端可验**：USB 直连与本地网络直连已在真机模拟器上跑通，但「对端跑 tailcat server」的链路、未授权提示、端口变化与 scrcpy 屏幕控制仍只有自动化测试与 `--demo` 覆盖。用这些功能时如果遇到问题，请附上「日志」页的片段。明细见 `docs/verification.md`。

### 变更

- 应用标识（macOS Bundle ID / Windows 应用 ID / Linux 桌面文件名）改为 `cc.nicoi.tailcat-manager`。凭据库服务名同步改为 `cc.nicoi.tailcat-manager.connections`，但**旧的 `cc.coauto.…` 仍然会读**：升级后已保存的连接地址不用重新输入，写入一律落在新名下。
- 「日志」页、Logcat 页与「资源」页的筛选框都换成搜索框（带放大镜图标、非空时右侧有清除按钮、Escape 也能清空）：**按 Enter 才生效**，不再每敲一个字母就重查一次（资源页是重排两张表）；清空输入框会立刻取消筛选。
- 所有表格换成 myGo 内置表格并统一加上圆角边框：列宽调宽后表头跟着内容横向滚动，拖动列宽的抓手不会再跑出窗口抓不到（原来最右一列的抓手会被裁在可视区外）。
- 资源页的应用 / 进程两个列表可按应用名、进程数（进程视图为进程名）、CPU、GPU、内存排序：点表头升序、再点降序，默认按应用名称升序；「不可用」的 GPU 永远排在数字后面。
- 资源页的分组行改为行首的「展开 / 收起」箭头按钮，不再点整行展开（键盘上下键因此在表格里照常可用）。
- 窗口标题栏的根面包屑由「我的设备」改为「首页」：它下面的页面不止设备，还有缓存、DERP、日志与工具设置；「我的设备」仍是侧栏里的设备分组名。
- 打开缓存管理 / DERP 节点 / 日志 / 工具设置时不再高亮侧栏里的设备行：管理页不显示某台设备，留着一条高亮的设备读起来像"这些数据属于它"。缓存管理第一次打开仍落在刚才那台设备上。
- 「工具设置」从弹窗改为侧栏菜单里的独立页面（首页 › 工具设置）：列出 ADB / scrcpy 各自解析到的路径，缺失的工具可直接安装，保存后留在页面上；侧栏底栏只保留两个工具的健康状态。
- DERP 节点页改为上下两块：「新建 DERP 节点」与「默认节点」固定在上半部，预设节点与最近用过的来源合成一个带边框的滚动框；预设列表按实际条数撑满，不再最多只显示 8 行。

### 修复

- 窗口与任务栏按钮显示的图标：以前是 Windows 的默认图标（空白窗口），因为可执行文件里虽然有了图标资源，窗口却没有设置自己的图标；现在打开窗口时按内嵌的 PNG 设置，`go build` / `go run` 的产物也一样。
- 「设备需要处理」的对话框以前只画一帧就消失，点不到里面的按钮；现在只要还有未处理的事件就一直显示，直到选择其中一个动作。
- 多台设备同时断开（例如在终端执行 `adb kill-server`）时只弹**一条**提示，写明「N 台设备的本地 ADB 入口同时消失」并列出设备名，动作用「全部重新连接」一次带回所有设备；单台断开仍是原来的三个动作。
- 从 Logcat 页切到其他页面不再卡 1–2 秒：停止 logcat 进程不再占用界面线程（Windows 上杀进程树实测约 0.8 秒），退出应用时仍会等它停干净再退。
- Logcat 页「跟随最新」打开时现在会立刻贴到最新一条，不用先手动滚到底部；从暂停继续、重新进入页面同样会跳到最新。
- Logcat 页每行最右的复制按钮固定在右侧：不能再被拖动到别的列位、也不能被拉宽，窗口缩到约 600 像素前都留在可视区内。
- 离开设备的「终端」页签、或从设备页切到别的页面时不再卡一下：停止 adb shell 不再占用界面线程（Windows 上实测约 0.8 秒），退出应用时仍会等它停干净。
- Logcat 页暂停时改「标签 / 内容」筛选不再没反应：暂停冻结的是新行自动进来，不是说页面不能搜；筛选会立刻在整个缓冲里重算。
- Logcat 页的「标签」列下面多了一行灰字，显示这条日志的进程名（应用就是包名），每 10 秒随进程表刷新，断开连接时清空。
- Logcat 页的时间、级别、PID、标签、内容都可以用鼠标拖选，⌘C / Ctrl+C 复制选中的那一段；行尾的复制图标仍然一次拿走整条（含多行堆栈）。
- Logcat 页的「清空缓冲」现在把「已接收 / 丢弃」计数一起归零：清空后仍显示「已接收 39400 行 · 显示 0 条」读起来像还有三万多行没显示出来。
- Logcat 页不再把同一次调用的多行日志（异常堆栈）拆成一条一条：logcat 给这些行相同的时间戳、进程与 tag，现在会合并成一条显示，堆栈恢复成一块。
- DERP 节点页的预设列表不再被藏起最后几行：表格按 "每行至少多高" 估算高度时，带按钮的行实际更高，最后几行就落到表格自己的滚动条后面；现在每行统一高度，表格高度与内容严格相等。
- DERP 预设列表里那条压着「删除」的竖向滚动条没了：卡片高度漏算了表头下的 1 像素分隔线，表格就差这 1 像素、在右边缘画了自己的滚动条。「操作」列也加宽到 200 并让它随窗口伸展，三个按钮不再贴着表格边缘（固定宽度的末列还会在边缘画一条调整抓手的细线，读起来也像滚动条）。

### 新增

- Logcat 页往上滚看历史时（此时不再自动跟随），底栏会出现「已暂停跟随」和「跳到最新」，点一下回到正在写的行，不用再和不断变长的列表拔河。
- 侧栏设备列表下新增「Logcat」：选一台已连接的设备实时查看 logcat，可按级别（最低级别语义）、标签、内容关键词筛选，可暂停、跟随最新、清空缓冲；日志流只在内存里，离开页面即停止，设备断开或 adb 退出后显示「日志流已结束」并可手动重新开始。
- Logcat 页可把当前筛选结果导出为 .txt（系统保存对话框里选保存位置），一行一条带完整日期与标签的输出，方便把一段日志发给别人或存档。
- Logcat 的缓冲从 5000 条提高到 30000 条，并加了一条 16 MB 上限（设备打超长行时先撞这条，内存不会被撑爆）；页面现在能一直滚到缓冲里最早的一条——原来即使缓冲里有 5000 条，也只显示最新的 2000 条。
- Logcat 底部在丢弃过数据时会写出缓冲上限（如「丢弃 29800 条（上限 30000 条 / 16 MB）」），不用再自己猜缓冲有多大。
- Logcat 页的「内容」列改为自动换行、完整显示，长消息与异常堆栈不再被截成一行加省略号；每一行末尾有复制图标，点一下就把这一条（含多行堆栈）放进剪贴板。
- 侧栏设备列表下新增「缓存管理」：按设备列出已缓存的应用名称与图标（包名、大小、读取时间、是否过期），可删除单条或清空这台设备的缓存；清空会作废当时正在进行的读取，不会清完又被写回来。
- 侧栏设备列表下新增「DERP 节点」：集中列出默认节点、保存的节点与最近用过的来源；可新建与编辑 JSON 节点，URL 型可立即重新获取并查看区域与节点；正在被设备使用的节点不允许删除。
- 侧栏设备列表之下新增「日志」页：应用自己的错误与警告、所有设备的通道日志、设备任务合成一条时间线，可按设备、级别、时间段筛选，并用空格分隔的关键词模糊搜索（任务输出里的文字也能搜到，点任务行可看完整输出）；日志与任务一起存进 `history.db`，关掉应用再打开仍能查。
- 设备页新增「文件」标签页：整个浏览区分左右两栏，用和终端一样的边框框住。左边是以 `/` 为根的文件夹树（`sdcard`、`system`、`storage` 都在它下面；`/sdcard` 这类符号链接按文件夹处理并与真目录排在一起），右边是当前文件夹的条目表格（名称 / 大小 / 修改时间 / 权限，文件夹排在前面），上方路径是可点的面包屑，可以一路点回上层。
- 文件页会**提前读取下一级**：展开一个文件夹后，它的子文件夹内容在后台依次读好，点进去立刻就有内容，不用再等（跳过 `/proc`、`/sys`、`/dev`、`/acct` 这类伪文件系统）。
- 文件夹树的展开箭头只在**真的还有子目录**时出现：没读过的目录先给箭头，读过发现是空的就收起来，不会出现「展开后什么都没有」的箭头；读取中与读取失败直接标在目录行上（转圈 / 红色「读取失败」，悬浮看原因），不往树里插额外说明行。
- 点文件行弹出属性弹窗，可把文件下载到本地，也可把本地文件上传到这个文件夹；设备文件系统一般不保存创建时间，因此不显示该字段。
- 设备页新增「资源」标签页：显示 CPU 型号与核心数、GPU 型号、内存总量，并用圆环进度显示 CPU、GPU、内存占用（圆环中间直接写当前占用率）；下方按应用分组列出设备上所有进程的 CPU / GPU / 内存占用，点分组行可展开看每个进程。
- 资源页新增「应用 / 进程」分段切换：进程视图一行一个进程，显示进程名与 PID、所属应用、CPU / GPU / 内存，两组各自记住列宽与滚动位置。
- 资源页新增筛选框：可按应用名、包名或进程名模糊筛选（子序列匹配，空格分隔多个关键词，全部命中才显示）；命中子进程时保留并自动展开它所属的应用；无匹配时显示「没有匹配的应用 / 进程」。
- 应用名称与图标默认**不解析**：读一个应用要从设备解压它 APK 里的清单与资源表，通过 tailcat 时不便宜。每行在名称后有一个「解析应用信息」按钮，按需只读这一行；工具栏的刷新按钮一次读取列表里的全部应用。解析出来的名字在分组行显示应用图标与应用名称（不是包名），图标缺失时用首字母圆形头像。
- 应用名称与图标在本地缓存 7 天；ADB 在线时可在分组上方的操作栏点「刷新应用信息」强制重新读取。
- 内容区分页：设备列表页与设备详情页，设备页在窗口标题栏里显示「我的设备 › 设备名」面包屑，可点「我的设备」返回；支持后退/前进（⌘[ / ⌘] 或 Alt+← / →），返回时自动选中该页对应的设备。
- 详情页新增「编辑」入口，可直接修改该设备的名称、连接方式、地址与端口。
- 详情页新增「终端」标签页，内嵌真终端（Ghostty 的无 cgo 实现），是一块独立的深色面板（黑色背景、浅色文字、圆角与边框），不跟随窗口的浅色外观；分两种模式：
  - **设备 Shell**：已连接时就是 `adb -s <serial> shell`，命令在该设备的 shell 中执行；
  - **ADB 命令**：按行执行任意 adb 子命令（`pull`、`push`、`shell`、`install` …），不需要写 `adb` 与 `-s`，命令作为任务记录并进入历史；
  - 未连接时终端里打印「设备未连接」并说明原因，输入的命令不执行、直接返回，同时弹出错误提示。
- 设备编辑器会记住用过的自定义 DERP 中继（保存在本地配置 `relayHistory` 里），选「自定义」可直接从历史里挑之前用过的来源。
- 设备页「日志」改为只读文本视图：可滚动、可选中复制，并按时间合并通道日志与设备任务；内容为空时给一句说明而不是空白框。往回翻看时页面会暂停追加，滚回底部自动补上，不会被新日志拽回末尾。
- 技术文档：`docs/architecture.md`（架构、状态机、两种连接方式、干预检测、安全设计、决策记录）、`docs/build-notes.md`（依赖版本、体积与构建耗时实测）、`docs/ui-and-console.md`（界面布局、路由与内嵌终端）、`docs/device-detail-page.md`（设备详情页与资源页的采样、分组、应用信息缓存与页面优化实测）。
- 仓库规则 `AGENTS.md`，说明硬约束、TDD 流程、常见改动路径与红线，并规定 GUI 一律优先使用 onevra 组件。
- 变更记录 `docs/CHANGELOG.md`（本文件）；实施计划 `docs/superpowers/plans/2026-11-15-gui-layout-and-direct-device-fixes.md`（布局修复）、`docs/superpowers/plans/2026-11-16-remaining-work.md`（打包、真机验收与记录、启动问题页、聚合提示、任务历史、托盘提示；2026-11-17 按当时的变更记录重排过一次）、`docs/superpowers/plans/2026-11-17-ui-feedback-round-2.md`（标题栏导航、日志时间线、按钮层级、中继历史）、`docs/superpowers/plans/2026-11-18-device-file-manager.md`（设备文件页，含计划完成后四轮真机反馈的修复记录）、`docs/superpowers/plans/2026-11-19-appmeta-cache-page.md`（应用信息缓存管理页，以及三个页面共用的侧栏入口与路由骨架）、`docs/superpowers/plans/2026-11-19-derp-map-page.md`（DERP 地图列表、详情、增删改与预览抓取）与 `docs/superpowers/plans/2026-11-19-logs-page.md`（统一日志：应用与设备日志入库、时间段与模糊搜索；设备页日志标签与日志页复用同一份实现，只查本设备）。

### 变更

- 设备编辑器里的 DERP 中继改为一个合并列表：保存的预设与之前用过的来源同时可选（预设在前、同一来源只列一次）；选中预设后下方来源框变为只读（URL 直接显示，内联地图显示区域/节点摘要），要自己填就选「自定义（不用预设，可输入内容）」，它会清空来源框并恢复可编辑。
- 设备编辑器里的自定义 DERP 来源改用多行文本框，长 JSON 不再挤在一行里；来源下拉改为应用内列表并左对齐（原来的系统菜单把文字居中，读起来像一组按钮）。
- DERP 节点详情页的标题栏面包屑补上列表层级：我的设备 › DERP 节点 › 名称，点「DERP 节点」回到列表。
- DERP 节点页的「默认节点」一行写明 tailcat 使用的节点文件地址（`https://tailcat.dev/derpmap.json`），并且只统计通过 Tailcat 连接的设备：本地 ADB 直连设备不使用 DERP，不再被算成「默认节点有 1 台设备在用」。
- 统一用词：界面不再出现「官方」字样（默认节点是 tailcat 的公共文件，本应用不替它表态），也不再叫「DERP 地图」——derpmap 只是一种 JSON 格式，界面上统一叫「DERP 节点」。
- 退出资源页再回来不再重新读取设备：读数保留到断开连接，重新进入直接显示上次的数字。
- 解析应用信息时该行显示加载中指示器，不再点了没有任何反馈。

- GPU 使用率只在该设备提供厂商计数节点（高通 kgsl / devfreq / MTK）时显示，其余设备在 GPU 一列显示「不可用」，不会显示 0%；占用百分比第一帧显示「—」，第二次采样起才有数。

- 应用内语言固定为简体中文，组件库自带的文案（如提示条上的「关闭」）随之变成中文。
- 应用启动后落在设备列表页，而不是直接进入某台设备的详情。
- 顶部窗口操作（添加设备 / 临时连接 / 测试全部设备）只在设备列表页显示，进入设备页后隐藏；「工具设置」移到侧栏底栏。

- 移除「外部终端」按钮与背后的系统终端调用（`platform/terminal_*.go`、`core.TerminalCommand`）：内嵌终端已覆盖同一用途。
- 移除「在终端中执行 shell 命令」按钮，以及侧栏底部的「新建临时连接」（临时连接仍可从列表页工具栏发起）。
- 侧栏分组可折叠：「我的设备」「临时设备」用折叠面板呈现，标题带数量，折叠后仍能看出有几台。

- 错误一律以错误级提示弹出，不再只塞进详情页或被忽略：连接失败、探测失败、刷新信息失败、屏幕控制失败、安装 APK、上传、复制失败、终端命令失败、组件安装失败。成功动作（复制、保存临时设备）改用成功级提示；表单字段校验仍内联显示。
- 设备任务不再单独显示在页面底部的面板里，改为并入该设备的「日志」页；运行中的任务在日志页顶部一键取消。
- 被截断的文字现在可以悬浮看全文：侧栏设备名与状态行、设备卡片的名称与连接方式、连通测试表的设备名与「路径 / 详情」。

### 修复

- 修复「新建 DERP 节点」里点「取消」或「保存」导致应用崩溃（窗口直接退出）：对话框里的分页控件在关闭动画期间会引用上一帧的界面元素，改为与设备编辑器相同的分段按钮；同时加了源码级检查，禁止再在对话框里放该控件。
- **在右侧双击进入文件夹后，左侧的文件夹树不跟着走**：树上原本只把祖先展开，却不移动高亮，光标一直停在一开始选中的那一行（通常是 `/`），看起来左边完全没反应；如果之前把 `/` 收起来过，左侧更会只剩一个折叠的 `/`，而右侧已经进了几层子目录。现在右侧进到哪个目录，左侧树就展开到哪、把那一行选中并滚动到可见位置（包括重新展开 `/`）。
- 「跟随最新」开关点不动/关不掉：开关的状态写入比组件报告的"已改变"早一帧，页面因此没保存新的值。现在按开关的实际取值判断，点一下就能关（再点一下恢复）。
- 日志页没有内容时页面会塌下来：时间线区域现在始终占满剩余空间，「这段时间没有日志」居中放大显示，底部动作行固定在最下面；「刷新」移到该行「清空日志」的左边（设备页的日志标签同样如此）。
- 日志页出现两条内容完全相同（同一毫秒、同一来源、同一文本）的日志时，控制台会不断打印 `two elements under one parent have the key ...`，跟随新日志还可能把其中一条当成已存在而丢掉。现在每一行用数据库自己的行号作键，内容一样的行各占一行。
- **打不开的文件夹（`/cache`、`/data` 这类只有 root 能进的目录）一直停在「正在读取」**：页面每一帧都重试，而每次重试都先把刚记下的失败原因清掉，于是既没有结果也没有原因，后台还在不停发命令。现在失败会粘住，只有点「重试」才重来，并且写明「没有权限查看该文件夹：…」。
- **没有下级目录的文件夹仍显示向下箭头**：为了让用户能收回展开状态，空目录曾被保留箭头，读起来像是里面藏了东西。现在空目录一律不给箭头（包括已展开的）。
- **可展开的文件夹展开后再收缩，箭头消失**：折叠的节点被当成叶子，不再画箭头。现在折叠与展开都会显示箭头，只有「确实没有子目录」才收起来。
- **同一个目录在树里出现两次**（`/` 下的 `storage/emulated/0` 与并列的捷径根）：导致两行共享一个状态，控制台不断报 `have the key`。现在树只有 `/` 一个根，目录只出现在它自己的位置上。
- **两个同名文件夹共享同一行状态**（`/sdcard/Download` 与 `/system/Download`）：树原来用名字当行标识。现在用完整路径，同名目录各走各的。
- 文件页读取失败不再给出一个空白表格或转瞬即逝的提示：区域中央写明原因并提供「重试」。
- 资源页采样从 21 秒降到约 1 秒（真机实测 0.8 秒）：每个进程原来要 fork 三个命令（`head`/`grep`/`tr`），现在只用 shell 内建命令；CPU 型号、GPU 型号等连接期内不变的信息改为连上后只读一次，且不再挡在第一帧数字前面。
- **「解析应用信息」一直转圈、点了没有反应**：读取 APK 里的清单与资源表原来要经过 `adb shell`，而它的 PTY 会把二进制内容里的换行改写成回车换行，解析因此永远失败、每次都退回下载整个 APK（实测 `Google Play services` 158 MB / 14.65 s）；同时读取结果没有任何回传通道，界面只能盲等 2 分钟。现在条目改为不经终端的 `adb exec-out` 读取（同一个包 14.65 s → **1.78 s**，普通应用 0.37 s），并且每一行都有确定的结果：读到就出名字，读失败就在行内写「无应用包」或「读取失败」并悬浮说明原因。
- **从未连接过的设备在侧栏缺少状态行**：会话的零值状态标签是空字符串，于是「从未连接」显示空白、而「连接过一次再断开」显示「未连接」；直连设备还会出现只有「· 127.0.0.1:5555」的孤立一行。现在新会话的默认状态就是「未连接」，直连设备显示「未连接 · 127.0.0.1:5555」。
- **装在第二个用户下的应用显示「无应用包」**：采样读的是整台设备的进程，而查 APK 的 `pm path` 只按当前用户回答，于是装在另一个用户（工作资料、车载的第二个账户）里的应用被判成「没有应用包」，且不再重试。现在改为按全部用户查找（`pm list packages --user all`），实测该设备上这类被误判的分组从 5 个归零；代价是取路径的往返耗时从 112 ms 变成 98 ms，可忽略。
- 设备上没有应用包的进程（系统服务、`system_server` 之类，实测占 96 / 120 行）不再提供注定失败的重试按钮，也不会每 10 分钟重问一次；要让这类行重新确认，重新连接设备即可。
- 应用包超过 64 MB 且读不出条目时直接说明「应用包过大，未读取」，不再赌一次 60 秒的整包下载。
- 「刷新应用信息」不再灰着等 30 秒：改为按每行的最终结果收敛并显示「正在读取应用信息 x/n」，同时跳过设备上并不存在的应用包；点单行解析时该行优先于整批刷新。

- 资源页与日志页的滚动区域不再伸到窗口底边之外（此前最后一行会被窗口裁掉、滚动条贴边）；资源页的 CPU / GPU / 内存三项改为等宽显示，过长内容以省略号收尾并悬浮看全文。
- **执行命令后界面卡死**：通道日志直接写历史库，而写入发生在管理器锁内，一旦写库变慢（SQLite 检查点、杀毒软件扫描磁盘），界面每帧读锁都会被阻塞。现在日志先进内存队列（容量 256，满则丢弃），由独立协程写库；历史库自己的提交队列同样不阻塞，满时跳过该条记录。
- **「取消测试」点了弹窗不关**：它只停止探测，看着却像个关闭按钮；而测试本身是一打开对话框就自己开始的。现在测试由用户点「开始测试」发起，关闭移到右上角，且关闭即中止批次。
- **同一条提示显示两遍**：内嵌横幅在内容区底部和侧栏底栏各画一次（例如「ADB 已配置完成」），而且不会自己消失。现在这类消息只以提示条出现一次。
- **关闭「添加设备 / 编辑设备」对话框时应用崩溃**：对话框里的中继分段控件在关闭动画期间引用了上一帧的界面元素，直接 panic（`element from pass N used in pass M`）。现在对话框内用一个按组件库取色绘制的分段选择器（`ui.SegmentedBase`），既没有跨帧引用，也没有丢掉分段控件的外观；这条坑写进了 `docs/ui-and-console.md` 的陷阱清单。
- **「编辑」「复制 ADB 地址」几乎看不见**：它们用的是无底色无边框的幽灵按钮，和正文糊在一起。现在幽灵样式只保留给文字里的链接（标题栏面包屑）与对话框里紧挨主按钮的「取消」，页面级动作一律用描边/填充按钮；列表页工具栏的主次也重新区分（「添加设备」最重）。
- **设备页回不到设备列表**：面包屑画在内容区里，而内容区没有让出窗口浮动标题栏的高度（标题栏高 `max(48, 系统标题栏高度, 主题行高)`，且盖在内容之上用于拖拽窗口），点「我的设备」的落点全被标题栏吃掉了。现在面包屑放在窗口标题栏内，内容区也整体让出了标题栏高度。
- **任务面板压住页面**：它是第二个整高列，从第一台任务起就从顶部开始绘制，盖住页面标题，并把标题裁成 0 尺寸。先改成"页面占满 + 面板贴底"，面板本身随后被删除——任务并进该设备的「日志」页（见「变更」）。
- 设备型号 / 代号 / Android / 序列号 / Shell 权限只在点「刷新信息」时才有：现在连接成功后自动读取一次，断开或连接失败时清空，不会残留上一台设备的信息。
- 终端离开页面再回来显示 `[Process exited]` 且无法再输入：页面卸载时关闭控制台、回来重建；程序意外结束时也会自动重建。
- 本地直连设备仍显示「探测链路」，点了只会得到「没有有效连接凭据」：该项按连接方式隐藏。
- 直连设备的 ADB 不可用（离线或超时）时应用会崩溃（空指针），因为失败处理仍试图关闭一条并不存在的 Tailcat 通道。
- 本地直连设备连接时误报「设备没有有效连接凭据」：连接流程在直连分支之前仍去取 Tailcat 地址，取不到就直接失败。现在直连设备完全不碰地址与凭据库。
- 直连设备详情页显示并不存在的「远端端口 5555」与「DERP 中继」，让人误以为配置有误。
- 侧栏设备行被拉伸到整列高度（布局用了同时占满宽高的 `Fill()`），现在每行固定高度，列表可滚动。
- 侧栏顶部内容被窗口浮动标题栏压住，折叠按钮与「我的设备」重叠。
- 侧栏设备行的内容被居中、选中底色是直角：改为左对齐并带圆角。
- 底部信息与「新建临时连接」在设备列表里重叠、互相覆盖。
- **「缓存管理」的条目一多就滚不动**：表格直接铺在页面上，超出窗口的部分（包括底部的「清空这台设备的缓存」）既没有滚动条也滚不到。现在标题与设备选择固定，条目列表在页内滚动，清空按钮始终可见。
- 「缓存管理」删除单条应用信息时，如果该应用正好有一次读取在后台运行，读到的名字和图标会被写回、条目重新出现；现在这次读取随删除一起丢弃，删除立即生效。

### 新增

- **内嵌传输层**：`github.com/tailscale/tailcat` 以库的方式使用，转发、探测、客户端身份、DERP 地图全部在进程内完成。**不再需要安装 `tailcat` 命令行**，只需 `adb`（必需）与 `scrcpy`（可选）。
- **每设备独立会话**：每条通道有自己的本地端口（固定或 5556–5655 自动分配）、自己的 ADB serial、自己的 Tailcat 身份，可多台同时连接、互不串台。
- **本地 ADB 直连**：添加设备时可选「本地 ADB 直连」，填 `IP:端口` 或 USB 序列号（如 `emulator-5554`），走本机 adb server，不经过 Tailcat、不使用设备身份。`IP:端口` 会先执行 `adb connect`，USB 序列号不会。
- **外部干预检测与「等待处理」**：在本机执行 `adb disconnect`、或设备被映射到别的本地端口时，应用会停下来让用户选 **重新连接 / 改用其他本地端口 / 稍后处理**，不再默默重试、也不会把用户刚断开的连接又偷偷连回去。
- **历史库**：任务、通道日志、批量连通测试结果存入 `<配置目录>/history.db`（SQLite，纯 Go 驱动），重启后任务面板仍有上次的记录。删掉该文件即清空历史，不影响使用。
- **批量连通测试**：一键测试全部设备的 Tailcat 可达性，3 台并发、每次时长上限、可取消，显示延迟与直连/中继路径，不建立也不断开 ADB 连接。
- **组件安装**：按平台自动安装缺失工具（macOS `brew`、Windows `winget`、Linux `apt`/`dnf`/`pacman`），Homebrew 会关闭自动更新/升级/清理；无法自动安装的组合（如 winget 的 scrcpy）会明确提示手动安装并支持手填路径。
- **设备操作**：安装 APK、上传、下载（含本地目录选择）、单条 Shell 命令、终端、屏幕控制（scrcpy）、链路探测、刷新设备信息（型号/代号/Android/序列号/Shell 权限）。
- **界面**：侧栏分组（我的设备 / 临时设备）、底部工具健康状态、概览与日志两页、任务面板、托盘菜单（每设备子菜单）、关闭窗口保活、单实例（第二次启动唤回已有窗口）。
- 演示模式 `--demo`：模拟设备，不读配置、不碰凭据库、不执行真实命令。

### 变更

- 会话状态由 7 个改为 8 个，新增「等待处理」（`needsAction`）。
- 断开顺序：先关闭本地监听与活跃连接、再执行 `adb disconnect`（原 Swift 版相反），避免断开后又接进新连接。
- 端口就绪判定：绑定成功即就绪，不再解析 stderr、不再有 5 秒等待。
- 设备身份改为由本进程生成/读取（格式与 `tailcat --key=` 完全一致，0600），不再交给外部命令行。
- 凭据长度上限改为 2560 字节（Windows 凭据管理器的最小上限，三平台统一）。
- Windows 的进程终止为整树 `taskkill /T /F`（无 SIGTERM 可用）。

### 移除

- **外部 `tailcat` 可执行文件依赖**（工具设置里不再有该路径，安装器不再提供它）。
- **`tailcat-adb` 地址簿导入**（配置目录里的地址簿路径、`legacyUsername` 字段、工具栏「导入地址簿」按钮）。CLI 模式已移除，也没有从 Swift 版迁移数据的需求 **（破坏性）**。
- **CLI 外部会话识别**（`bridges/*.pid`、`ps`/`lsof` 扫描、socat 桥归属）：应用现在只管理自己建立的通道。
- 内联 DERP JSON 的本地回环 HTTP 服务（库直接接受内存中的 DERP 地图）。
- macOS 凭据助手可执行文件：改用系统凭据库直连，代价是开发期 `go run` 重建后可能再要一次 Keychain 授权。

### 修复

- 脱敏输出在超长行（>32 KiB）之后会连带丢弃紧随其后的正常行；现在只丢弃该行到下一个换行为止。
- 监视循环与干预检测互相等待造成死锁（持有管理器锁时再次上锁）。
- 历史库关闭后再写入会因向已关闭通道发送而 panic。
- 首次启动时配置目录尚不存在，导致历史库无法打开；现在先创建目录（0700）。
- 历史库"写入后立刻读取"可能读到空结果（队列未排空）。

### 安全

- 连接地址（`tc...`）只存系统凭据库，配置文件、日志、任务输出、tailcat 日志全部经过脱敏；跨多次读取被切断的凭据也不会露出半截。
- 配置目录 0700、配置文件 0600，身份目录 0700、私钥 0600，写入原子化并拒绝符号链接。
- 身份文件存在即复用，损坏时报错并保留原文件，绝不静默换钥；同名并发初始化由文件锁保证只生成一次。
- 设备私钥只以路径与 `nodekey:` 公钥出现在日志中，私钥仅在进程内存中使用。

### 依赖

- 新增 `github.com/egoist/mygo` v0.9.1（GUI，纯 Go）、`github.com/oneo-me/onevra/source` v2026.18（组件库）、`github.com/tailscale/tailcat` v0.7.0（传输，含 `tailscale.com` 传递依赖）、`modernc.org/sqlite` v1.62.0（纯 Go SQLite）。
- 要求 Go 1.27.3 及以上。
- 单文件体积：默认 46.9 MB、`-ldflags "-s -w"` 后 32.5 MB（Windows/amd64 实测）。

- 尚未在真机上联调：ADB 实链路、scrcpy 窗口、设备授权流程、干预弹窗都只有自动化测试与 `--demo` 验证。
- 未产出 dmg / msi / deb 安装包与签名。

- 历史只有"重启后载入任务面板"，没有按设备/时间筛选的界面。
